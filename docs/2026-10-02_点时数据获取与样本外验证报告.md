# 点时数据获取与样本外验证报告

更新日期：2026-10-02（Asia/Shanghai）

## 当前结论

项目已经具备严格历史月包的导入链和内置逐日特征生成器。当前本机 `cache/backtest/history.db` 同时保留原探测数据集 `jq-strict-probe-202607`、3 只股票的小样本，以及本轮实际获取并导入的 `akshare-price-core-202401-202512-broad-v1`：20 只股票、9,694 条日线/状态/股票池记录、2024-01-02 至 2025-12-31。AkShare 数据明确是 `price_core` 代理研究数据，不能支持严格点时策略结论。

已另外导入长周期数据集 `akshare-price-core-201801-202512-broad-v1`：20 只股票、37,325 条日线/状态/股票池记录、2018-01-02 至 2025-12-31。该数据集仍是 `proxy_only=true`，只用于价格核心的跨市场阶段验证。

`long_cycle_validation.py` 现在是长周期验证入口，除回测和 Walk-forward 外，还会生成等权买入并持有代理、月度/年度收益、Sharpe/Sortino、回撤持续时间、市场阶段归因、股票与行业归因、成交额参与率容量代理、零/双滑点、双费用和交易 Bootstrap 报告，并单独计算生产资格门禁。

本轮补充了三项能力：

1. `joinquant_strict_history_exporter.py` 已补齐 `build_daily_feature_rows`，从当日及以前的历史日线计算 MA、ATR、支撑/压力、突破、趋势、仓位、止损、止盈、行业和市场状态，并将决定时间固定在当日收盘后的 `15:00 +08:00`。缺少 30 个有效历史日或前收盘价时跳过该股票日并留下有界审计。
2. `history_acquisition.py` 提供有界 AkShare 日线采集器，输出项目统一的 `bars.csv`、`status.csv`、`universe.csv` 和来源元数据。Eastmoney 接口不可用时会回退到 AkShare 的 Tencent 接口；回退接口的成交额是“成交量（手） × 100 × 收盘价”代理，元数据会明确记录这一限制。所有结果仍标记为 `proxy_only=true`，仅允许 `price_core` 研究。
3. `historical_backtest.py walk-forward` 提供训练窗口选参、滚动验证窗口和最终保留集。参数只在训练窗口选择，验证窗口和 holdout 不参与排序；不足 21 个交易日预热或不足 3 段窗口时失败关闭。

这些是价格核心代理结果，不是严格历史结论。验证窗口虽然为正，但最后 holdout 为负且只有 8 笔闭合交易；固定参数回测的高换手和成本占比也说明当前结果不能据此上线。代理成交量/成交额、历史状态、股票池和涨跌停信息仍有缺口，必须用 strict 月包和模拟盘观察继续验证。

回测费用采用版本化 `FeeSchedule`：买卖佣金默认万三、单边最低 5 元，卖出印花税默认千分之 0.5，A 股过户费默认双边万分之 0.1（0.01‰），交易规费作为券商佣金的一部分处理，买卖各 10bp 模拟滑点。上交所公开的投资者费用说明也列出卖出单边印花税、最低 5 元佣金和双边 0.01‰ 过户费；接入券商后必须以实际交割单和成交回报校准，不能把 `simulation-only-v1` 当作实盘费用证明。

## 推荐数据路径

### 主路径：JoinQuant strict 月包

这是当前项目最契合的路径。项目已经有以下完整链路：

```text
output/聚宽严格历史导出.py
  -> JoinQuant Research 按月运行
  -> strict ZIP
  -> scripts/strict_history_upload.ps1
  -> strict_history_ingest.py
  -> cache/backtest/history.db
  -> historical_backtest.py validate/run/walk-forward
```

每个月包需要包含：

- `bars.csv`
- `status.csv`
- `universe.csv`
- `features.csv`
- `decision_candidates.jsonl`
- `candidate_prices.jsonl`
- `strict_manifest.json`
- `metadata.json`

需要特别区分两条当前导出能力：现有快照现在把 `require_daily_features=True` 和内置 `build_daily_feature_rows` 绑定到严格导出入口，会生成覆盖 `STRICT_FEATURES` 的 `features.csv`。要让 `historical_backtest.py --mode strict` 通过，仍必须实际运行并导入包含完整逐日特征的 JoinQuant 月包；当前本地 AkShare 数据集没有这些点时特征，不能把价格核心结果升级为 strict 结论。当前内置生成器的中性政策是：没有可证明发布时间的历史新闻时 `news_score=0`，没有点时概念源时以历史行业作为确定性 `theme` 回退。

严格模式要求每个启用因子具备 `available_at <= decision_at`，并且按历史日期重建股票池、行业、ST、停牌、复权和交易状态。不能用当前快照补历史，也不能把 `price_core` 的代理结果升级为 strict 结果。

建议先补齐最近已经成熟的完整月份，再连续导入至少 6 个月；最后一个月要留出 D+10 价格路径成熟时间。导入顺序按月份进行，每个月都要保留数据集哈希、包哈希和导入报告。

### 次路径：AkShare 日线代理

运行方式：

```powershell
.venv\Scripts\python.exe history_acquisition.py `
  --codes-file cache\backtest\codes.txt `
  --start 2024-01-01 `
  --end 2026-06-30 `
  --dataset akshare-price-core-202401-202606 `
  --output-dir cache\backtest\acquisition\akshare-price-core-202401-202606 `
  --db cache\backtest\history.db
```

该路径适合：

- 检查本地价格核心指标和撮合逻辑；
- 做参数敏感性和压力测试；
- 在等待 JoinQuant strict 月包时先验证回测流程。

它不适合证明完整策略有效性，因为当前接口不能在一次调用中保证历史 ST、停牌、历史股票池、历史行业、财务发布时间和精确涨跌停状态。采集器会在 `acquisition_metadata.json` 中记录这些限制并设置 `strict_eligible=false`。

通过命令行 `--db` 导入时，统一表头的文件使用 `akshare_canonical` 来源标识；这只用于保留真实来源审计，不会改变 `proxy_only=true` 的质量门。

### 不建议作为主路径的方案

直接从通用行情网站下载今天的全量股票列表，再回放到过去，会引入生存者偏差。直接使用当前行业、当前 ST 或当前财务值，也会引入未来信息。任何第三方数据源都必须先转换为项目的统一表和 `available_at` 契约，再进入 strict 校验。

## 样本外和 Walk-forward 使用方式

```powershell
.venv\Scripts\python.exe historical_backtest.py walk-forward `
  --db cache\backtest\history.db `
  --dataset <dataset_id> `
  --start 2024-01-01 `
  --end 2026-06-30 `
  --mode strict `
  --output-dir output `
  --folds 3 `
  --holdout-days 20 `
  --min-score-grid 70,75,80 `
  --max-positions-grid 4,8,12
```

报告输出到 `output/historical_walk_forward_latest.json`，同时输出质量报告。每个窗口包含训练区间、验证区间、候选参数、训练指标、选中参数和验证指标；最后的 holdout 使用最后一个训练窗口选出的参数，完全不参加参数排序。

当前实现只做研究评价，不会写入 `approved`、`active`、部署或券商状态。要进入下一阶段，至少需要：

- 6–12 个月 strict 数据通过质量门；
- 3 个不重叠 walk-forward 验证窗口；
- 最后 20 个交易日 holdout；
- 每个验证窗口有成交和闭合交易；
- 手续费、滑点、涨跌停和停牌压力测试通过；
- 与 JoinQuant 原生回测或第二套本地引擎进行结果交叉核对。

## 数据获取落地顺序

1. 用当前策略快照在 JoinQuant Research 导出第一个完整成熟月，不改 manifest 和 ZIP 内容。
2. 使用上传脚本导入本地或服务器历史库，运行 `validate --mode strict`。
3. 连续导入 6–12 个月，确认每个月的候选和价格路径不是 0。
4. 运行 `walk-forward --mode strict`，先使用默认参数，再使用小范围参数网格。
5. 只有验证窗口和 holdout 都有足够闭合交易，才把报告状态从 `insufficient_evidence` 推进到 `complete`。
