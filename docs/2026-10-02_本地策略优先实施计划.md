## 2026-10-04 本轮策略改进实现

本轮按“先改善净收益质量，再保留券商接口边界”的顺序完成以下代码能力：

- `historical_strategy.py` 增加 `relative_v1` 价格核心 profile：横截面 20 日相对强度、20 日实现波动、成交额流动性比率和市场宽度；`legacy` profile 保留用于基线复现。
- `historical_backtest.py` 增加 `liquidity_v1` 动态滑点模型、最大成交额参与率和最短持有日；所有成交仍按 T 收盘决策、T+1 开盘撮合，费用继续由版本化 `FeeSchedule` 提供。
- Walk-forward 可以在训练窗口选择 `alpha_profile` 和 `slippage_model`，验证窗口和最终 holdout 不参与选择。
- `history_acquisition.py --all-a-shares` 可以发现当前 A 股代码并批量采集代理日线；历史 ST、退市、成分和停牌仍不能由该入口补造，输出继续是 `proxy_only=true`。
- `paper_replay.py` 复用本地候选生成器，回放到有界 JSON 模拟账户，输出只保留最近100条事件，不写正式交易账本，也不调用券商适配器。

2025 年代理数据的首轮结果为：`relative_v1 + liquidity_v1` 净收益为负、相对等权代理为负，双滑点仍为负。因此该 profile 只能作为 Walk-forward 候选，不能因为因子数量增加而替换基线或进入生产。严格点时数据、完整历史股票池、连续模拟盘和券商成交回报仍是未完成门槛。

本地纸面回放命令示例：

```powershell
.venv\Scripts\python.exe paper_replay.py `
  --db cache\backtest\history.db `
  --dataset akshare-price-core-201801-202512-broad-v1 `
  --start 2025-01-02 --end 2025-12-31 `
  --output output\paper-replay\paper_replay_latest.json `
  --alpha-profile relative_v1
```

该回放使用本地 JSON 模拟账户，不能替代严格历史回测、JoinQuant 模拟盘或券商成交验证。

## 目标

先把项目完善为可复现、可解释、可持续观察的本地策略系统，再接入券商自动下单。券商接入暂时只保留平台无关的接口边界，不让具体券商 SDK 进入策略、回测或风控代码。

目标链路：

```text
权威行情与证券规则
  -> 时点数据与候选池
  -> 策略信号
  -> 组合构建与本地硬风控
  -> 回测撮合 / JoinQuant 模拟盘
  -> 账本、归因、对账和观察报告
  -> 未来 BrokerAdapter
```

## 当前基线

- 已有因子、候选池、PIT 严格历史、回测、分层退出、账本、风险检查、对账和 JoinQuant 模拟执行骨架。
- ML 保持关闭，只作为后续旁路观察能力。
- 当前本机 `compileall` 命令需要改用目录形式运行；直接传递 PowerShell 通配符会被 Python 当作字面路径。
- 本机 `.venv` 使用 Python 3.10.11 和 `requirements-py310.lock`；依赖检查已通过。每次业务改动后都必须重新运行全量发现，Linux `bash` 边界测试在 Windows 无 Bash 时明确跳过，不能把跳过项写成通过。
- `broker_adapter.py` 已提供平台无关协议和默认 `ManualAdapter`；它只生成 `manual_confirmation_required`，不提交订单、不伪造券商回报。
- 历史回测运行身份已覆盖完整规范化配置（包括 `max_positions`、`min_score`、费用契约和实现代码），结果落库带确定性 `result_sha256`；失败运行可用同一身份安全重试。
- 本地 JSON 模拟账户已带 schema 版本、可注入时钟、交易/净值历史上限和损坏文件拒绝策略，避免因文件异常静默恢复初始现金。
- `history_acquisition.py` 已增加有界 AkShare 日线采集器。它只生成明确标记的 `price_core` 代理数据，记录历史 ST、停牌、股票池、涨跌停和点时因子缺口，不把代理数据升级为 strict 证据。
- `joinquant_strict_history_exporter.py` 已补齐内置 `daily_feature_builder`：使用不晚于交易日的 30 日历史计算技术特征和风险字段，并在 strict 导出元数据中记录生成器版本与点时政策。
- `historical_backtest.py walk-forward` 已增加训练窗口选参、至少 3 段滚动验证和最终 holdout；参数只在训练窗口排序，不写入 approved/active 状态。
- 当前不把 QMT 节点、真实券商登录或自动下单作为本阶段完成条件。

本轮在本地实际取得并导入 `akshare-price-core-202401-202512-broad-v1`：20 只股票、9,694 条日线，覆盖 2024-01-02 至 2025-12-31。`price_core` 回测、3 折 walk-forward 和 20 个交易日 holdout 均可运行；最新 walk-forward 的验证窗口复合收益为 +2.41%，但最后 20 个交易日 holdout 为 -0.36%，且只有 8 笔闭合交易。固定参数回测净收益为 +7.49%，其中佣金约 3,550 元、印花税约 1,384 元、过户费约 56 元、滑点约 5,577 元。所有结果仍是 `proxy_only=true` 的价格核心研究证据，不代表 strict、模拟盘或券商执行已经验证。

本轮继续获取并导入 `akshare-price-core-201801-202512-broad-v1`：20 只股票、37,325 条日线，覆盖 2018-01-02 至 2025-12-31。针对价格核心策略补充了横截面 5/20 日市场状态估计，并根据逐信号成本研究将 CAUTION 状态的新开仓关闭。当前参数版本为 `signal-gate-caution-off-v2`：4 个最大持仓、最低分 75、每日最多新仓 2 个、冷却 5 日。固定回测净收益约 -0.005%，最大回撤 8.58%，换手 67.66 倍，Profit Factor 1.002；3 折 walk-forward 复合收益 -5.11%，利润因子 0.891，最大回撤 6.44%，最后 60 个交易日 holdout +0.46%，但只有 9 笔闭合交易。风险下降且固定回测接近盈亏平衡，但样本外窗口仍不稳定，不能推进生产。

已新增 `long_cycle_validation.py` 长周期验证套件和 `signal_research.py` 信号质量研究工具。最新报告显示策略相对等权持有代理超额 -13.95%，零滑点净收益 +7.22%，双滑点净收益 -6.70%，双费用净收益 -6.79%，Bootstrap 总收益为正的概率 49.2%；逐信号研究显示 1/3/5 日净收益仍为负，10 日平均净收益约 +0.14%，但中位数仍为负。这些结果支持继续研究和模拟盘观察，不支持生产发布。

本轮新增 `local_entry_policy.py`，把未来券商下单前也需要满足的价格跳空、组合总暴露、行业集中、相关性历史、目标收益覆盖交易成本和组合开放风险检查抽成平台无关纯函数；历史回测通过 `--local-entry-gates` 显式启用。价格核心入场增加趋势确认、最大追涨 ATR、最高分异常区间过滤和连续两日信号确认，回测定仓严格使用 T+1 开盘可见价格，不再使用当日收盘价估算买入时组合市值。市场风险退出保留为 `--market-risk-exit` 可选实验开关，未经独立验证不默认启用。

最新候选参数版本为 `trend-confirmation-v4`：4 个最大持仓、最低分 75、最高分 94.999、趋势确认、最大追涨 2.5 ATR、连续两日确认、每日最多新仓 2 个、冷却 5 日、组合开放风险上限 4%、本地入场经济门启用。2018-01-02 至 2025-12-31 代理回测净收益 +1.60%，最大回撤 4.69%，Profit Factor 1.112，换手 20.64 倍；相对等权持有代理超额 -12.35%，去掉最高 3 笔收益后净收益为负，仍不能视为稳定盈利或生产参数。

同一候选的压力测试固定入场规则、只替换执行费用：零滑点 +5.10%，双倍滑点 -0.21%，双倍费用 +0.09%。双倍成本接近盈亏平衡，说明还需要真实成交回报校准和更强的信号边际。

生产边界仍独立于回测：当前长周期数据是 AkShare `proxy_only`，strict 门禁会拒绝；没有真实券商行情/规则、实际费率和成交回报校准，也没有完成模拟盘连续观察、断线/重启/未知提交/部分成交演练。因此长周期验证已启动并完成价格代理阶段，生产资格仍未通过。

回测费用采用版本化 `FeeSchedule`：买卖佣金默认万三、单边最低 5 元，卖出印花税默认千分之 0.5，A 股过户费默认双边万分之 0.1（0.01‰），交易规费作为券商佣金的一部分处理，买卖各 10bp 模拟滑点。实际券商费率必须通过环境变量或券商成交回报覆盖，不能把 `simulation-only-v1` 当作实盘费用证明。

## 阶段一：可复现基线

目标是让任何干净环境都能运行相同测试和回测。

1. 增加明确的 Python 版本、依赖约束和开发测试依赖；本地 Python 3.10 锁定在 `requirements-py310.lock`。
2. 建立 Windows/Linux CI：编译、单元测试、数据库迁移、备份恢复、策略快照验证。
3. 所有时间相关测试注入 clock，禁止依赖系统当前日期和工作区缓存。
4. 让测试使用临时数据库和临时运行目录；运行产物只写入 `cache/` 或 `output/`。
5. 修复当前测试导入错误、时间敏感失败和 Python 3.10 SQLite/PowerShell 兼容性，并记录可重复的测试报告。

验收：`.venv\\Scripts\\python.exe -m unittest discover -s tests -p "test_*.py" -q` 在本地通过；Linux 专属测试只在存在 `bash` 时运行。通过不等于真实交易日验证。

已加入 `.github/workflows/ci.yml`，在 Windows/Linux、Python 3.10/3.12 矩阵执行依赖安装、编译和全量单测；迁移/备份/快照专项仍由后续门禁补充。

## 阶段二：策略与数据契约

目标是保证同一数据、代码和参数一定产生同一策略结果。

1. 为每次策略运行生成 `run_id`、代码提交号、策略版本、参数版本、数据版本和结果哈希。
2. 统一股票池、交易日历、公司行为、ST/停牌/退市、涨跌停和最小交易单位校验。
3. 为每个特征记录 `available_at`，并在候选生成前统一执行反前视检查。
4. 明确买入、持有、减仓、止损、止盈、退出和重复信号的优先级。
5. 把策略配置、费用配置、滑点配置和证券规则配置从代码中抽离并版本化。

验收：同一输入可重放；任何未来数据、缺失关键证据或版本哈希不一致都会失败关闭。

## 阶段三：真实交易假设下的回测与组合

目标是让回测结果能解释真实模拟盘行为。

1. 完善信号到成交的延迟、下一根 K 线成交、部分成交、撤单、涨跌停、停牌和 T+1。
2. 统一手续费、印花税、滑点、最小佣金和资金冻结模型。
3. 增加组合级仓位、行业/主题暴露、现金缓冲、换手预算和相关性约束。
4. 输出净值、回撤、换手、成本占比、容量、基准超额和交易归因。
5. 通过 `output/聚宽严格历史导出.py` 获取真实 6–12 个月 strict 月包；AkShare 采集器仅用于等待期间的 price_core 代理研究。
6. 完成至少 3 段 walk-forward、20 个交易日 holdout、参数敏感性和压力测试。

验收：回测能生成逐笔交易、组合曲线、风险报告和样本外报告；任何 proxy 数据不能冒充 strict 证据。

## 阶段四：模拟盘观察

目标是验证策略在连续交易日中的实际运行行为。

1. 继续使用 JoinQuant 作为模拟执行环境。
2. 连续观察信号、订单、成交、账户快照、持仓同步和通知 outbox。
3. 记录跳过、拒单、部分成交、延迟和本地账本差异。
4. 验证重启、断网、重复信号、缓存陈旧和 kill switch。

验收：至少 10–20 个有效交易日没有未解释的账本差异、重复信号或高优先级死信。

## 阶段五：券商接口预留

本阶段只建立稳定协议，不实现具体券商平台：

```python
class BrokerAdapter:
    def get_account(self): ...
    def get_positions(self): ...
    def get_orders(self): ...
    def get_trades(self): ...
    def submit_order(self, intent): ...
    def cancel_order(self, broker_order_id): ...
```

当前已实现 `broker_adapter.py` 中的平台无关 `BrokerAdapter` 协议和 `ManualAdapter`：它只返回 `manual_confirmation_required`，不会伪造券商已受理。测试用 `PaperAdapter`、QMT 和券商 API 后续再实现。策略层只生成标准 `ExecutionIntent`，不直接调用券商 SDK。

## 暂不实施

- QMT/miniQMT Windows 节点和真实券商登录
- 多券商路由和高级执行算法
- ML 参与买卖或自动调参
- 自动参数批准、自动模型发布和真实资金交易

## 每阶段交付规则

每次改动必须同时提交：代码、针对性测试、运行证据和文档状态。任何功能只有在测试通过、可重放、可观察后，才能从 `implemented` 推进到 `observed`；真实券商接入另行建立发布门禁。
